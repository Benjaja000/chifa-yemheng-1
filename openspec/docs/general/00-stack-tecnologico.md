# 3. Base de datos (intocable salvo ALTER aditivo)

```yaml
database:
  provider: Supabase
  engine: PostgreSQL
  access: { method: node-via-express }   # pg / supabase-js service_role SOLO en backend
  primaryKeys: { strategy: integer-identity }
  # id_* INTEGER GENERATED BY DEFAULT AS IDENTITY. PROHIBIDO UUID
  # (46 tablas + seeds + USP ya operan así).
  namingConvention: { tables: snake_case, columns: snake_case }
  audit:
    enabled: true
    fields: [usucre, pccre, feccre, usumod, pcmod, fecmod, estado]
    # PROHIBIDO created_at/updated_at/created_by/updated_by.
  softDelete: { enabled: true, strategy: estado-A/I/E }   # PROHIBIDO deleted_at
  auth: { provider: propio }        # ver §4, NO Supabase Auth
  storage: { enabled: true }        # solo imágenes de productos (menu-carta.md)
```

# 6. Reglas de negocio (solo códigos del catálogo)

Catálogo: `openspec/docs/REGLAS_DE_NEGOCIO.md` (79 códigos). Toda regla nueva
debe citar un `BR-*` existente o proponerse formalmente antes de codificarse.

```yaml
businessRules:
  - BR-RES-052  # reserva online nace P sin mesa, confirma SAL_RESERVA con mesa libre
  - BR-ACC-055  # NC solo supervisor (VEN_NOTACREDITO) + motivo + serie 07
  - BR-DER-030  # pago único por venta (no mixto)
  - BR-RES-015  # anular pedido solo si no facturado; si no, NC
  - BR-ACC-035  # login personal sha256 + bloqueo 3 intentos
  - BR-ACC-044  # cliente Gmail obligatorio + auditoría LOGIN
  - BR-ACC-036  # menú por unión de roles/permisos
  - BR-GPS-001  # GPS opcional, nunca bloquea (fallback manual)
  - BR-GPS-002  # distancia solo sugiere costo_envio
```
